## 运行结构

- 前端：`/var/www/play-island/releases/<release>/`，`current` 链接选择版本。
- 账号服务：`/opt/play-island-api/releases/<release>/`，`current` 链接选择版本。
- systemd：`play-island-api`，仅监听 `127.0.0.1:8092`。
- Nginx：`/etc/nginx/snippets/play-island.conf`。`/games/api/` 转发账号服务，`/games/` 提供静态文件，现有其他站点保持原路由。
- 运行时：`/opt/play-island-node/node-v24.21.0-linux-x64/`。来自 https://nodejs.org/dist/v24.21.0/ ，部署前校验官方 SHA-256。
- 私有账号与存档：`/var/lib/play-island/`，权限 700，数据文件权限 600，服务用户 admin。此目录独立于版本，更新与回退均不会删除。
- 每次发布备份：`/home/admin/play-island-backups/<release>/`。
- 上传目录：`/home/admin/play-island-upload/<release>/`。
- ECS 连接资料：`D:/CREATE/CODE/APP/aliyun/`。SSH 私钥从本机使用，不打包上传。

账号采用随机盐 scrypt 密码摘要与 HttpOnly / Secure / SameSite Cookie，Cookie 仅作用于 `/games/`。会话保存在进程内，服务重启需重新登录；账号和存档保留。当前是单进程小规模实现，不能同时启动多个服务实例写同一数据目录。

## 更新流程

1. 运行 `npm run check` 和 `npm test`（也可用 Node 22+ 执行 `node --test tests/*.test.js`）。
2. 用 UTC 版本号运行 `node deploy/build.js <release>`；将目录内文件打成 `site.tar.gz`。
3. 运行 `node deploy/build-backend.js <release>`，将 `<release>-backend` 目录打包为 `backend.tar.gz`。仅含 `server.js`、`accounts-api.js`、`sea-save.js`、`sea-weapons.js`、`sea-campaign.js` 和摘要，不含 `.data`。共享战役及武器目录必须一起发布。
4. 上传两个压缩包、`install.sh`、`play-island.conf`、`play-island-api.service` 到本次上传目录。
5. 执行 `bash /home/admin/play-island-upload/<release>/install.sh <release>`。
6. 成功后更新本机 `latest-release.txt`，执行 `python deploy/verify.py`，结果写入 `verification.json`。

构建前端包含页面、脚本、样式、游戏 PNG 与 SVG、录音 MP3 和音效来源说明，共 64 个文件。后端代码、账号文件、测试与部署脚本不公开。首次安装会下载独立 Node 运行时，不改动系统 Node 或其他应用。

安装会备份配置及原版本链接，停止账号服务后复制私有数据至备份目录（权限 700），验证压缩包摘要，启动仅本机可访问的后端，检查 Nginx 配置，平滑重载后等待 HTTPS 接口就绪。失败时恢复旧配置、静态版本、后端版本和服务配置，并退出非零状态。20261014T024124Z 首次发布遇到 Nginx 重载过渡期的 404，自动回退成功；正式发布增加有限重试后健康检查通过。

## 备份与手动回退

备份 `/var/lib/play-island/` 的整个目录，作为敏感数据妥善保存，不放入网页目录或代码仓库。应在维护窗口停止账号服务后复制，确保账号列表和各账号存档一致，复制后恢复服务。

回退时恢复该次备份的 Nginx 配置和服务文件，分别将两个 current 链接切回 `previous-release` 与 `previous-backend` 记录的版本，执行 systemctl daemon-reload、重启 play-island-api、nginx -t 和平滑重载。首次引入服务前没有旧服务配置；回退到纯静态版本时需停用 play-island-api。任何回退都保留账号数据。
